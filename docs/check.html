JExec Check

Declare an intended execution. The engine runs the published protocol rules — deterministically, in your browser, sending nothing anywhere — and returns a verdict, the failure classes behind it, and a JExec Record.

This is a rules engine, not an oracle: it evaluates what you declare. Its honesty about that limitation is the point — the same is true of every admissibility boundary. The rules are identical to the table on the Protocol page; if they ever diverge, that is a governance incident.

What to do with the verdict

A DENY or ESCALATE names its failure classes; each links to its reference page with remediation. Fix the declaration — or the reality behind it — and run the boundary again. To grade the whole execution path rather than one execution, use the JExec Admissibility Standard — or request a human-performed Execution Admissibility Review.

JExec Check runs entirely client-side. It transmits nothing, stores nothing, and has no way to know whether your declarations are true — which is why the record it emits says “as declared.”
